### F-03 — Security gate was materially under-scoped
**Severity:** P1 security.

The authoritative `.github/workflows/security-scan.yml` executed Gitleaks but its documented security posture also referenced OSV/SAST controls that were not part of this blocking security workflow. `osv-watch.yml` is a scheduled/generated-main workflow, not a substitute for a PR security gate. No Bandit SAST or dependency audit was enforced by the security gate.

**Fix:** add blocking Bandit SAST for repository Python execution surfaces and `pip-audit --strict` to the existing security workflow, with the Bandit report retained as an artifact.

### F-04 — Main branch protection remains a control-plane blocker
**Severity:** P0/P1 security governance.

The repository documentation records `main` as unprotected with required-status enforcement off. A direct attempt to read GitHub's branch-protection endpoint during this audit returned HTTP 403 from the connected integration, so the control-plane state could not be independently re-verified in this session.

**Fix status:** repository-code remediation is not sufficient. This remains an explicit external/control-plane action and must not be marked complete from documentation alone. Issue #159 remains the authoritative tracking item.

**Severity:** P2 documentation hygiene.

Historical reports still mention removed workflows such as `release-package.yml`, `build-graph.yml`, and the nonexistent `jsonld-export.yml`, and old reports retain obsolete workflow counts and graph placeholder findings.

These are historical artifacts and should not be rewritten as if they never existed. The risk is only that an agent may mistake them for current architecture.

**Fix policy:** authoritative current documents must explicitly identify current architecture; historical reports remain immutable evidence. Current audit/index documents should point agents to the current sources.

## Architecture assessment

The current architecture is materially coherent around one canonical source and deterministic projections. The following boundaries are verified and should not be duplicated:
- canonical `skills/`
- Universal Registry runtime
- single graph generator/writer
- single search generator
- single JSON-LD export pipeline
- deterministic Agent Skills reconciliation/projection
- deterministic Agent Skills discovery publication
- single production release writer
- single repository-controlled Pages deployment

The next architectural gap is not another index or generator. The remaining product-level gap is broader evidence-backed registry coverage and the controlled transition from taxonomy-backed recommendation inputs to registry-backed authoritative inputs. That transition must not be forced while registry coverage is intentionally small.
